# GA4 イベント設計

> 2026-08-01 作成。Track 5 の一環。
> **実装前に「⚠️ 先に解消すべき問題」の判断が必要**。

---

## ⚠️ 先に解消すべき問題 — プライバシーポリシーと実態の食い違い

現行のプライバシーポリシー（`docs/privacy-policy.md`、App Store とアプリ内からリンク）には
次の記述があるが、**Web版では事実と異なる**。

| 行 | 記述 | Web版の実態 |
|---|---|---|
| 21 | 「外部サーバーへのデータ送信は一切行いません」 | ❌ GA4 が Google に送信している |
| 41 | 「本アプリは、分析ツール（アナリティクス）や広告SDKを使用していません」 | ❌ GA4 を使用している |

GA4 は 2026-04 のコミット `4fd0f51`「GA4アクセス解析を導入（LP + アプリ本体）」で
LP（`public/lp.html`）と Web アプリ本体（`deploy-web.yml` が `dist/index.html` に注入）に
導入済み。ポリシーの更新が漏れていた。

**iOS 版は問題なし。** ネイティブビルドは `dist/index.html` を使わないため GA4 は入っておらず、
App Store の「Data Not Collected」宣言および「完全オフライン動作」の記述は正確。

### なぜ先に直す必要があるか

- 日本の**電気通信事業法・外部送信規律**（2023-06 施行）では、利用者情報を第三者へ送信する場合に
  通知または公表が必要。GA4 は該当する。現状はその逆の記述をしている
- ポリシーは App Store の審査項目でもあり、アプリ内からもリンクしている
- **この状態でイベントを増やすと乖離が拡大する**。計測の追加より先に開示を正すのが順序

### 対応案（実装とセットで行う）

`docs/privacy-policy.md` を Web版 / iOS版で分けて記述する。

```
## データの保存について
本アプリで入力されたデータ（運動の選択、回数・セット数の設定、注意メモ等）は、
すべてお使いのデバイス内にのみ保存されます。外部へ送信することはありません。

## アクセス解析について（Web版のみ）
Web版では、サービス改善のため Google アナリティクス（GA4）を使用しています。
- 収集する情報: ページの閲覧、ボタン操作、選択された運動の種類、Cookie 等の識別子
- **収集しない情報**: 指導書の目的、運動ごとの目的、患者への注意メモ、検索語など、
  利用者が入力した文章は一切送信しません
- 送信先: Google LLC（同社のプライバシーポリシーに従って取り扱われます）
- 無効化: ブラウザの Cookie 設定、または Google のオプトアウトアドオンで停止できます

iOS アプリ版はアクセス解析を使用しておらず、一切の外部送信を行いません。
```

あわせて `app/preview.tsx` の「端末内で完結 · クラウド送信なし」は
**「患者データは端末内で完結」**に変更する（PDF・入力内容が送信されないことは事実だが、
Web版でGA4が動いている以上「クラウド送信なし」は誤読を招く）。

## 1. 何を知りたいか（3つだけ）

計測は「見て終わり」になりがちなので、**次の意思決定に直結する3つ**に絞る。

| # | 知りたいこと | 判断に使う先 |
|---|---|---|
| ① | 出力までのファネルのどこで落ちるか | UI改善の優先順位 |
| ② | 実施チェック表は実際に使われるか | C-1 の価値検証（アンケートC見送りの代替） |
| ③ | どの運動がよく選ばれるか | イラスト2枚化 Batch 10 の選定、追加運動の選定 |

## 2. イベント定義

対象は **Web版のみ**（LP + アプリ本体）。iOS ネイティブには入れない。

### ファネル（①）

| イベント名 | 発火 | パラメータ |
|---|---|---|
| `app_open` | アプリ本体の初回表示 | — （GA4 の `page_view` で代替可） |
| `exercise_select` | 運動を選択 | `exercise_id`, `body_part`, `category` |
| `sheet_edit_open` | 「指導書を作成」で調整画面へ | `exercise_count` |
| `pdf_export` | 「PDFを出力・共有」を押下 | `exercise_count`, `orientation`, `check_sheet`, `has_purpose` |

`has_purpose` は**目的が入力されたかどうかの真偽値のみ**。内容は送らない。

### チェック表（②）

| イベント名 | 発火 | パラメータ |
|---|---|---|
| `check_sheet_toggle` | トグル操作 | `enabled`（true/false） |

ON率は `pdf_export` の `check_sheet` パラメータでも取れるため、
トグル操作自体の計測は「迷って切り替えたか」を見る補助。

### 運動の人気（③）

`exercise_select` の `exercise_id` を集計する。
詳細モーダルを開いた回数も、検討されたが選ばれなかった運動を知る手がかりになる。

| イベント名 | 発火 | パラメータ |
|---|---|---|
| `exercise_detail_open` | サムネイルの i をタップ | `exercise_id` |

### 絞り込みの使われ方（補助）

| イベント名 | 発火 | パラメータ |
|---|---|---|
| `filter_apply` | 部位/姿勢/種類の選択 | `filter_type`, `filter_value` |
| `search_use` | 検索を使った（デバウンス後1回） | `result_count`, `has_result` |

**`search_term`（検索語そのもの）は送らない。** GA4 標準の `search` イベントは
`search_term` を伴うのが通例だが、利用者が誤って患者名等を入力する可能性を排除できないため、
独自イベント `search_use` として件数のみを送る。

## 3. 絶対に送らないもの（実装時の不可侵ルール）

利用者が自由入力した文章は、**例外なく送信しない**。

- `sheetPurpose`（指導書の目的）
- `purpose`（この運動の目的）
- `notes`（患者への注意）— 患者情報が入りうる最大のリスク箇所
- 検索語（`searchText`）
- 頻度のカスタム入力

送ってよいのは **アプリが定義済みの値のみ**（運動ID、部位、カテゴリ、件数、真偽値、向き）。
実装では「文字列を受け取ってそのまま送る」関数を作らず、
**送信可能な型を限定したラッパー**を1つ用意して、そこ以外から gtag を呼ばない。

## 4. GA4 側の設定 ✅ **設定済み（2026-08-01 実機確認・変更）**

プロパティ: トレさく（`a392524838p534420731` / 測定ID `G-J12ZXEXNSN`）

| 項目 | 設定値 | 備考 |
|---|---|---|
| イベントデータ保持 | **14か月** | 既定の2か月から変更した |
| ユーザーデータ保持 | 14か月 | 変更なし |
| Google シグナル | **オフ** | 広告目的の連携なし |
| Google 広告とのリンク | なし | |

| 拡張計測機能・その他 | オン | ページビュー/スクロール/離脱クリック/フォーム操作/動画/ファイルDL |
| データストリーム | **ウェブ1件のみ** | iOS/Androidストリームなし＝iOS未計測を裏付ける |

**カスタムディメンション（イベントスコープ・6件登録済み）**

| 表示名 | パラメータ |
|---|---|
| 運動ID | `exercise_id` |
| 部位 | `body_part` |
| 運動カテゴリ | `category` |
| 絞り込み種別 | `filter_type` |
| 絞り込み値 | `filter_value` |
| 用紙の向き | `orientation` |

登録しないとパラメータがレポートに出ない（イベント件数しか見えない）ため必須。

### ⚠️ サイト内検索を必ずオフのままにすること

拡張計測機能の「サイト内検索」は**URLのクエリパラメータから検索語を自動収集する**。
現在のトレさくは検索語をURLに載せないため実害はなかったが、
「検索語を送信しない」という開示を設定面でも担保するためオフにした。
**URL設計を変更する際は、この設定が意図せず効き始めないか確認すること。**

## 5. 実装方針

- `src/utils/analytics.ts` を新設。**Web以外では何もしない no-op** にする
  （`Platform.OS !== "web"` で早期return。ネイティブに混入させない）
- 送信関数は型で縛る。自由文字列を受け取る口を作らない
- GA4 未ロード時（ブロッカー等）は握りつぶす。計測失敗でアプリが壊れないこと
- LP側は既存の `page_view` のみで十分（CTAクリックは必要になってから）

```ts
// 送れるものを型で限定する（自由入力を通す口を作らない）
type Ev =
  | { name: "exercise_select"; exercise_id: string; body_part: BodyPart; category: Category }
  | { name: "exercise_detail_open"; exercise_id: string }
  | { name: "sheet_edit_open"; exercise_count: number }
  | { name: "pdf_export"; exercise_count: number; orientation: Orientation;
      check_sheet: boolean; has_purpose: boolean }
  | { name: "check_sheet_toggle"; enabled: boolean }
  | { name: "filter_apply"; filter_type: "body_part" | "posture" | "category"; filter_value: string }
  | { name: "search_use"; result_count: number; has_result: boolean };
```
