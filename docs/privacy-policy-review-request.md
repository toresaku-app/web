# プライバシーポリシー改訂のレビュー依頼

> 2026-08-01 作成。`docs/privacy-policy.md` の改訂版を公開前にレビューしてもらうための依頼書。
> レビュー完了後、指摘を反映してから別リポジトリ（`toresaku-app/privacy-policy`）へ反映する。

---

## 背景

「トレさく」は理学療法士が患者向けの自主トレ指導書を作成し、PDF出力するアプリ。
**Web版（ブラウザ）と iOS アプリ版**があり、患者データはすべて端末内で完結する設計。

2026年4月に Web版（LP + アプリ本体）へ Google アナリティクス（GA4）を導入したが、
**プライバシーポリシーの更新が漏れていた**。その結果、以下の虚偽記載が約4ヶ月間公開されていた。

| 旧記述 | 実態 |
|---|---|
| 「本アプリは、分析ツール（アナリティクス）や広告SDKを使用していません」 | Web版はGA4を使用中 |
| 「外部サーバーへのデータ送信は一切行いません」 | GA4がGoogleへ送信中 |

今回この乖離を解消し、あわせて新規に追加したGA4イベント計測の内容を開示する改訂を行った。

**iOS アプリ版にはGA4は入っていない**（ネイティブビルドは Web の `dist/index.html` を使わないため）。
App Store の「データを収集しません」宣言は現時点で正確。

## 今回の改訂内容

- 「アクセス解析について」の節を新設し、**Web版とiOS版を分けて記述**
- 収集する情報／**収集しない情報**を列挙
- 送信先（Google LLC）と停止方法を明記
- 「データの保存について」の記述を「入力内容を外部サーバーへ送信することは一切ありません」に限定
- 「広告について」を独立した節に分離

## 今回追加したGA4イベント（実装済み・Web版のみ）

送信できる値を型で限定し、利用者の自由入力が混入しない設計にしている。

| イベント | 送信するパラメータ |
|---|---|
| `exercise_select` | 運動ID、部位、カテゴリ |
| `exercise_detail_open` | 運動ID |
| `sheet_edit_open` | 運動の選択数 |
| `pdf_export` | 運動数、用紙の向き、チェック表の有無、**目的が入力されたかの真偽値のみ** |
| `check_sheet_toggle` | ON/OFF |
| `filter_apply` | 絞り込みの種類と値（アプリ定義の選択肢のみ） |
| `search_use` | **検索結果の件数のみ（検索語は送らない）** |

**一切送信しないもの**: 指導書の目的、運動ごとの目的、患者への注意メモ、検索語、頻度の自由入力。

## レビューしてほしい観点

以下の順で見てほしい。**特に 1 と 2 を重点的に。**

### 1. 法令適合（最重要）

- **電気通信事業法の外部送信規律**（2023年6月施行）の通知・公表義務を満たしているか
  - 送信される情報の内容、送信先、利用目的が特定できる書き方になっているか
  - 「オプトアウトの方法」の記載として十分か
- **個人情報保護法**上の問題はないか
  - Cookie・GA4のクライアントIDの扱いについて、記載すべきことが漏れていないか
  - 「個人情報を収集しません」と「Cookie等の識別子を収集」が併記されている状態は、
    読み手に矛盾と受け取られないか。書き分けが必要か
- **医療系アプリ**として追加で求められる記載はあるか
  - このアプリは診断・治療を行わない「記録・出力ツール」の位置づけ（SaMD非該当を維持している）

### 2. 記述の正確性・整合性

- Web版とiOS版の書き分けが、読み手に誤解なく伝わるか
- 「本アプリ」という語が Web版とiOS版のどちらを指すのか曖昧な箇所はないか
- 「収集しない情報」の列挙が、かえって「他は全部収集する」という印象を与えないか
- 過去に虚偽記載があった経緯を踏まえ、**改訂履歴や更新の告知**を記載すべきか

### 3. 表現・読みやすさ

- 利用者（医療職。法務の専門家ではない）が読んで理解できる平易さか
- 冗長な箇所、削れる箇所はないか

### 4. 他ドキュメントとの整合（参考情報）

以下と矛盾していないか。矛盾があれば**どちらを直すべきか**も指摘してほしい。

- `docs/appstore-metadata.md` — ストア説明文に「完全オフライン動作」「外部サーバーへのデータ送信なし」の記載あり（iOS版のことなので正しいはずだが、表現として誤解を招かないか）
- `public/lp.html` — LPに「データは端末内のみ。クラウド送信は一切なし。」の記載あり。**LPはWeb版の入口でGA4が動いている**ため、この表現の妥当性を見てほしい
- `app/preview.tsx` — アプリ内に「患者データは端末内で完結 · 外部送信なし」の表示あり（今回「クラウド送信なし」から変更済み）

## 出力してほしい形式

1. **要修正**（法令・正確性の観点で直すべき箇所）— 該当箇所と修正案
2. **推奨**（直したほうがよい箇所）— 該当箇所と理由
3. **問題なし**と判断した観点

指摘は「どう直すか」まで具体的に書いてほしい。文面案があればそのまま採用できる形で。
