## 雇用に関する決定（2026-04-24）

### 決定：pm 職を追加雇用する
- 3エージェント並列運用で全体像が利用者の頭の中だけにある状態を解消するため
- 発端：3エージェント全員が `plan.md` の陳腐化を指摘
- 利用者問い：「全てを統括して plan.md を管理する役はいらないの？」
- 結論：必要。追加雇用する

### 決定：pm は「呼び出し型」運用とする
- **却下**: 4ターミナル常駐型 → 画面が窮屈になる、情報の鮮度も pm が常に起動している必要はない
- **採用**: 必要な時だけ起動（朝イチ / 作業後 / 週次振り返り / 境界チェック）
- **理由**: pm の仕事は episodic（非連続的）。常駐する価値よりセットアップ・メンテコストのほうが大きい

### 決定：pm は実装も決定もしない「情報整理役」に徹する
- **却下**: pm が各エージェントに直接指示を出す「ディレクター型」
  - **却下理由**: Claude Code にはエージェント間通信の仕組みがない。人間がハブである前提を崩すと全体が破綻する
- **採用**: pm → 利用者 → エージェント、の順で情報を流す「情報整理役」
- **権限**: Read 全域、Write は `plan.md` / `tasks/**` / `docs/*-plan.md` / `docs/*-tasks.md` / `docs/marketing-*.md` のみ

### 決定：Bash は読み取り系のみ
- `git status`, `git log`, `git branch`, `ls`, `cat`, `find` のみ許可
- `git commit`, `git push`, `git checkout -b` 等の状態変更系は禁止
- **理由**: 状態変更は app-developer の担当。pm が git を触ると責任が混線する

## 決定：cmo-advisor の「相談役モード」廃止、執行も担う通常モードへ戻す（2026-05-28）

- **経緯**: 2026-04-24 に cmo を「相談役モード」（コピー本文を書かない、利用者に書かせる、4 モード運用）へ移行していた。約 1 ヶ月運用した後、利用者から「相談役という枠を無くしたい。普通に作業もしてくれる人に変えてほしい」と要請
- **却下した案**:
  - 「相談役モードを維持しつつ部分的に執行解禁」→ 境界が曖昧になり、毎タスクで「これは執行 OK か」を確認することになる。利用者の運用負荷が増えるだけ
- **採用**: 相談役モードを **完全廃止**。cmo は通常モードに戻る
  - コピー本文・スライド構成案・ポスター原稿・キャンペーン文面など、依頼があれば執筆実行する
  - 4 モード（ヒアリング/講義/宿題/振り返り）の運用も解除
- **理由**:
  - 学会発表資料の作成（演題 2 / 10/8-9 本番）、アンケート C 設計、施設プラン B2B 営業文書など、執行が必要なタスクが連続する見通し
  - 利用者がマーケ実務の学習段階を一定こなしたため、相談役モードの目的（利用者の自走力育成）は概ね達成
  - 4 モード運用が現場で噛み合わず、相談と執行を分ける手間のほうが大きくなった

### 維持される境界（廃止しても変わらないもの）
- CLAUDE.md の不可侵ルール（効能表現禁止、SaMD 非該当維持等）
- 個人 PT 課金モデル・フリーミアム・疾患タグの再提案禁止（過去に却下済み）
- 実装は app-developer、運動データは exercise-curator（cmo は引き続き不可侵）
- PM 経由の inbox 配布フロー（cmo に直接指示しない原則）

### 反映先（pm 領域）
